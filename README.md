# oasis

一个从零写起的**在线多用户 Agent 后端**：FastAPI + PostgreSQL + Anthropic SDK（默认接 DeepSeek 的 Anthropic 兼容接口）+ 原生 JS 前端。

它不是框架，而是一份「把 Agent 服务里容易出错的地方一个个做对」的实现：每个功能都有能重跑的确定性测试，关键逻辑做过变异检查（把它改坏，测试必须变红），重要结论用真实模型验收过。适合用来学习 Agent 后端怎么做，也适合当试验台，在上面换新的模型、架构或技术。

> 学习项目，代码和注释以中文为主。

## 一条消息怎么走

```
POST /conversations/{id}/messages
  └─ 同一事务：建 run + 存用户消息 → 起后台 task，HTTP 立刻返回 202
后台 run（async generator，只产出事件，不碰数据库）
  ├─ 拼上下文：system → 会话上下文 → 摘要 + 原文 → 运行时尾部（越稳定越靠前，为前缀缓存服务）
  ├─ 超线时先清旧工具结果（确定的投影），还超线再做 LLM 摘要
  ├─ 调模型（流式）→ 截断就续写 → 有工具调用就：权限 → 参数校验 → 规则（允许 / 拒绝 / 要人确认）
  └─ 可并发的工具按组并行，要确认的挂起，run 结束、不占会话锁
runner：事件唯一出口，先写 run_events 拿到 seq，再推送（SSE 订阅者断线可按游标续播）
```

贯穿全项目的一条原则：**先写库，再做有副作用的事**。seq 先落库再推送；审批先落库再结束 run；取消意图先写库再取消；高风险工具执行前先记一行 executing；沙箱执行前先标「需要重置」。任何一步崩溃，库里都有足够的信息判断「做到哪了」，宁可标「结果未知」也不盲目重试写操作。

## 做了什么

**运行与流式**
- run 和 HTTP 连接解耦，断线不停 run；同一会话同时只有一个 running（部分唯一索引）
- 事件先落库再推送，续播「先订阅、再按游标查库」，不丢不重；多实例下用 LISTEN/NOTIFY 跨实例推送，慢消费者断开后按游标补齐
- 多实例 run 归属：租约 + 心跳 + fencing，属主崩溃后由别的实例接管收尾，用户在任意实例都能停止

**Agent 循环**
- 出口表：每个出口一个明确的 (status, stop_reason)，任何出口之后历史里都没有孤儿 tool_use
- 收尾轮、原样重复检测、同一工具反复「依赖不可用」时熔断
- 撞上 max_tokens 先续写（纯文本 / 只有 thinking / 截断的工具入参，截断的调用一律不执行）
- 已输出水位：一次模型调用推过字却没拿到结果就发 retract，屏幕上的字要么落进消息、要么被撤回
- 流开始以后的断网、流内过载由循环重试，不和 SDK 自带的重试叠加

**上下文**
- 四层拼装、前缀缓存友好；超线时压缩成摘要（CAS 提交、采用规则、单轮内切点、超窗被动恢复）
- 大工具结果写库前截断一次，全文另存、按 ref 回取（只能读本人的）
- 清旧工具结果：占位符确定、水位只升不降、够一批才清，清完前缀照常命中缓存（实测：请求小 57%，下一轮命中率 96%）

**工具与人在回路**
- 常驻 / 延迟两档工具 + tool_search + call_tool 代理，权限在服务端过滤
- 要确认的调用持久化挂起，决定接口用 CAS，续跑只执行一次；超时记「结果未知」
- 工具声明能否并发，按模型给的顺序分组并行；排在「要确认」之后的调用等批准后再按顺序执行
- 幂等键（= tool_use_id）+ 按键对账：结果未知的写操作按键查清，查不到要等过宽限期才判「没做」，带围栏防止卡住的旧进程醒来后重复落账

**知识库（RAG）**
- 向量 + BM25，RRF 只负责排序，相关性看 rerank 分数，阈值在带库外题的标注集上校准，搜不到敢说没有
- 按条目和标题切块，片段级指标；检索降级显式标记，一路带到模型面前
- 引用校验：代码核对回答里标的出处是不是依据所在的那一段，和忠实度评委交叉成四格表，分开「生成编造」和「归因错误」
- 查询改写（默认关）：只在第一轮弱时改写，原句一路保留，rerank 永远用原句

**子智能体、评测、沙箱、联网**
- 子任务只拿到 briefing、工具被裁剪、并发有上限也有超时；取消意图先写库
- 端到端评测：确定性断言优先（看库不看模型自述），LLM 评委只管忠实度且引文由代码复核；校准集 / 测试集划分、Wilson 区间
- trace：spans 表把一个 run 展开成调用树
- 代码沙箱（E2B 协议）：一用户一沙箱、一会话一内核，失败分「没开始 / 代码报错 / 结果未知」
- 联网搜索和抓取走模型服务商的服务端接口，抓取的风险随「这个链接见没见过」而变

## 跑起来

需要 Python 3.12+、[uv](https://docs.astral.sh/uv/)、Docker、Node（只跑前端单测时需要）。

```bash
docker compose up -d                      # 本地 PostgreSQL，端口 5433
cp backend/.env.example backend/.env      # 填入模型的 API key
cd backend && uv sync
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 http://127.0.0.1:8000 ，用演示 token `demo-token` 登录（另有权限更少的 `guest-token`）。知识库要配 SiliconFlow 的 key（embedding 和 rerank），沙箱要配 E2B 兼容的服务，联网工具用 DeepSeek 的搜索接口，都是可选的。

## 测试

```bash
cd backend
uv run pytest tests -q          # 需要 docker compose 里的 PostgreSQL；测试会自建 oasis_test 库
node --test static/*.test.mjs   # 前端事件归约、审批卡片状态机
```

测试全部用假模型、假 embedding、假 rerank，不连外网、不花钱。`scripts/` 下是要调真实模型的端到端脚本和评测（`agent_eval.py`、`kb_eval.py`），会产生费用。
